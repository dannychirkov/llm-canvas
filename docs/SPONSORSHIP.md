# Support LLM Canvas

LLM Canvas is an independent, Apache-2.0-licensed visual workspace for language models. It runs as a Windows, macOS or Linux desktop application, or as a self-hosted server. Users bring their own provider credentials and can connect compatible local model servers.

## The problem

Useful model conversations often branch: compare two approaches, examine a claim, attach source material, then combine the results. Linear chat makes it easy to lose track of which information belongs in each request. LLM Canvas puts those prompts, replies and connections on a saved graph, with an inspector for the context sent to each model.

## Why support it?

The project gives people a provider-independent way to experiment with prompts and connected workflows while keeping application data in an installation they control. Its desktop and headless distributions share one core. It is a release candidate with public source and downloadable previews; it is not yet a stable release or a managed service.

See the [README](../README.md), [screenshots](SCREENSHOTS.md), [release verification](RELEASE-VERIFICATION.md) and [current releases](https://github.com/dannychirkov/llm-canvas/releases) for what exists today. No user counts, growth metrics or performance claims are implied.

## What support would fund

| Priority | How support helps |
| --- | --- |
| Maintenance and reliability | Time for reproducible bug fixes, regression coverage and clearer documentation. |
| Provider compatibility | API credits and local-model testing for chat, streaming, image inputs/outputs and usage reporting. |
| Desktop distribution | Native CI capacity, Windows code signing, and macOS signing/notarization. Current previews are unsigned. |
| Usability and accessibility | Testing with real users, keyboard navigation, readable context inspection and first-run improvements. |

Useful non-financial contributions include API credits, access to test hardware, native-platform testing, design feedback and accessibility reviews. Provider contributions should help test compatibility without requiring users to choose that provider.

## Sponsorship and partnerships

I am interested in individual sponsorship, recurring maintenance support, and partnerships with model providers, local-model tools and organizations using visual AI workflows.

Recognition in the repository or release notes can be discussed, with your permission. There are no published paid tiers, guaranteed delivery dates, support SLAs or exclusive integrations. Scope, budget and any recognition should be agreed before a commitment. Sponsorship does not grant access to user data or credentials; the project remains Apache-2.0 licensed.

To start a conversation, [open a sponsorship inquiry](https://github.com/dannychirkov/llm-canvas/issues/new?title=Sponsorship%20inquiry). Include your organization or project, the kind of support you have in mind, and which area interests you. Keep the initial message public-safe; do not post financial details or personal contact information. We can arrange a private channel afterward.

No payment account is configured for this repository yet. A verified funding link and GitHub sponsor button can be added once a payment channel is available.
